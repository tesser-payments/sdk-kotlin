# Contributing to the Tesser Kotlin SDK

Public-facing user docs are in [README.md](./README.md). This file is for SDK maintainers and contributors: building, testing, and releasing.

---

## Local development setup

**Java 17.** Verify with `java -version`. On macOS:

```bash
brew install openjdk@17
echo 'export PATH="/opt/homebrew/opt/openjdk@17/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

Other tools that work: `sdkman install java 17.0.13-tem`, `asdf install java openjdk-17`, `mise use java@17`.

**Gradle wrapper.** No separate install needed; `./gradlew` is committed and pins Gradle 9.5.0 via `gradle/wrapper/gradle-wrapper.properties`.

**Verify your setup:**

```bash
git clone https://github.com/tesser-payments/sdk-kotlin.git
cd sdk-kotlin
./gradlew :sdk:test
```

You should see `BUILD SUCCESSFUL` with all tests passing.

## Build, test, lint commands

```bash
./gradlew build                # full build + test + ktlint + apiCheck (what CI runs)
./gradlew :sdk:test            # tests only
./gradlew :sdk:ktlintCheck     # lint
./gradlew :sdk:ktlintFormat    # auto-fix lint violations
./gradlew :sdk:apiCheck        # binary-compat lockfile check (sdk/api/sdk.api)
./gradlew :sdk:apiDump         # regenerate sdk/api/sdk.api after intentional API changes
./gradlew :sdk:publishToMavenLocal   # dry-run a release into ~/.m2/repository/xyz/tesser/sdk/
```

### Conventions

- **Single shared `Json` instance.** Every (de)serialization site uses `internal val json: Json` from `internal/util/Json.kt`. Don't construct ad-hoc `Json {}` blocks elsewhere.
- **Locale-safe string ops.** All `.lowercase()` / `.uppercase()` calls must pass `Locale.ROOT` (e.g., `"FOO".lowercase(Locale.ROOT)`). Avoids the Turkish-i bug class.
- **No emojis in committed files.** Plain ASCII. Section signs (`§`) and arrow glyphs are avoided in source files for terminal portability.
- **`explicitApi()` is on.** Every public symbol must be marked `public`. The Kotlin compiler enforces this in strict mode.

## Public-API binary compatibility

`sdk/api/sdk.api` is a lockfile generated by [`org.jetbrains.kotlinx.binary-compatibility-validator`](https://github.com/Kotlin/binary-compatibility-validator). It captures every public symbol the SDK exposes: classes, methods, fields, generic signatures.

**CI runs `apiCheck` on every PR.** A diff against the committed lockfile fails the build, which forces a deliberate decision when the public API changes.

### When you change the public API

1. **Regenerate the lockfile:**
   ```bash
   ./gradlew :sdk:apiDump
   ```
2. **Inspect the diff** in `sdk/api/sdk.api`. Confirm the change is intentional.
3. **Add a CHANGELOG entry** under `[Unreleased]`.
4. **Decide the SemVer impact:**
   - New public symbol added: minor bump.
   - Existing symbol changed or removed: major bump.
   - No public-API change (internal refactor): patch bump.

---

## CHANGELOG

Format: [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).

Add entries under `## [Unreleased]` as work lands. Use the standard subsection headings: `### Added`, `### Changed`, `### Fixed`, `### Removed`. Don't open new release blocks until cutting a release; the [release runbook](#release-process) does that.

## Release process

The release workflow at [`.github/workflows/release.yml`](./.github/workflows/release.yml) runs on every push to `main`. A `gate` job reads the project version from `gradle.properties` and skips the rest of the workflow if a `v<version>` tag already exists. To cut a new release, bump the version and push; the workflow does the rest.

### One-time setup (before the first real release)

These need to be configured once by a project maintainer. The release workflow is wired but inert until these are in place.

**1. Sonatype Central Portal account.**

Register at https://central.sonatype.com under the `xyz.tesser` namespace. Verify domain ownership via a DNS TXT record on `tesser.xyz` (Sonatype provides the verification token in their UI).

**2. GPG key for Maven Central signing.**

```bash
gpg --full-generate-key                                            # RSA 4096; passphrase recommended
gpg --keyserver keys.openpgp.org --send-keys <key-id>              # publish public key
gpg --keyserver keyserver.ubuntu.com --send-keys <key-id>          # secondary keyserver
gpg --export-secret-keys --armor <key-id> > /tmp/gpg-private.asc   # export for CI
```

Maven Central will refuse to release artifacts that aren't signed with a key whose public half is discoverable on a public keyserver.

**3. GitHub repo secrets.**

Go to `Settings, then Secrets and variables, then Actions` and add four secrets:

| Secret | Value |
|---|---|
| `SONATYPE_CENTRAL_USERNAME` | User token name from https://central.sonatype.com/account |
| `SONATYPE_CENTRAL_PASSWORD` | User token password (regenerate the token if you lose it) |
| `GPG_PRIVATE_KEY` | Full contents of `/tmp/gpg-private.asc`, including the `-----BEGIN PGP PRIVATE KEY BLOCK-----` and END headers |
| `GPG_PASSPHRASE` | The passphrase used during key generation, or empty if you generated without one |

After this is done once, every release runs end-to-end without further human intervention.

### Cutting a release

For each release, replace `0.0.X` with the actual version number you're cutting.

**1. Decide the bump** per [SemVer](https://semver.org/):

- **Patch** (`0.0.1 -> 0.0.2`): bug fixes, no public-API changes.
- **Minor** (`0.0.1 -> 0.1.0`): backward-compatible additions to the public API.
- **Major** (`0.0.1 -> 1.0.0`): breaking changes. Don't ship these casually pre-1.0.

**2. Verify the public API surface is up to date.**

```bash
./gradlew :sdk:apiDump
git status sdk/api/sdk.api    # clean if no API changes; commit the diff if not
```

**3. Bump the version** in `gradle.properties`:

```properties
version=0.0.X
```

This is the only place the version string lives. The release workflow grabs it via `grep '^version=' gradle.properties`.

**4. Cut the CHANGELOG block.** In `CHANGELOG.md`:

- Move every bullet under `## [Unreleased]` into a new heading: `## [0.0.X] - YYYY-MM-DD`.
- Re-add an empty `## [Unreleased]` block at the top with the standard subsection headings.
- Update the comparison URLs at the bottom: add `[0.0.X]: https://github.com/tesser-payments/sdk-kotlin/compare/v0.0.<X-1>...v0.0.X` and update `[Unreleased]: ...compare/v0.0.X...HEAD`.

**5. Update the install snippets in `README.md`** to reference the new version. Both the Gradle and Maven snippets carry the literal version string; search for the previous version and replace.

**6. Commit and push to main.**

```bash
git add gradle.properties CHANGELOG.md README.md sdk/api/sdk.api
git commit -m "chore: release v0.0.X"
git push origin main
```

**7. Watch the release workflow.** GitHub Actions runs `release.yml` automatically on the push. The `gate` job reads the new version, sees no `v0.0.X` tag exists, and runs the `publish` job: `./gradlew build` (tests + ktlint + apiCheck must pass) followed by `./gradlew :sdk:publishAndReleaseToMavenCentral`, then it pushes the `v0.0.X` git tag and creates a matching GitHub release with auto-generated notes. Total runtime is typically 3 to 5 minutes; the artifact appears on Maven Central within roughly 15 minutes after publish.

### If a release fails midway

| Symptom | Recovery |
|---|---|
| `./gradlew build` fails (test/ktlint/apiCheck) | Nothing was published. Fix on `main` and push another commit; the workflow re-runs from the gate. |
| Publish step succeeded but tagging failed | The artifact is on Maven Central but the tag wasn't created, so the next push retries the publish and fails on a duplicate-version error. Recovery: create the tag manually (`git tag v0.0.X && git push origin v0.0.X`) so the gate skips that version, then bump to `0.0.<X+1>` for further work. |
| Workflow seems hung | Check the Actions log. The Sonatype Central Portal API is occasionally slow during high traffic; uploads can stall but typically recover within roughly 10 minutes. |
| `https://central.sonatype.com` shows a staged-but-not-released bundle | Manual cleanup may be needed. Check the bundle status in the Central Portal UI; you can usually drop a stuck staging bundle via the UI. |

### Local credentials for `publishToMavenLocal`

If you want to dry-run a publish locally (signs and stages artifacts into `~/.m2/repository/`), copy `.envrc.example` to `.envrc`, fill in your Sonatype user token and the path to your exported GPG key, and run `direnv allow`. Then `./gradlew :sdk:publishToMavenLocal` will use those credentials automatically.
